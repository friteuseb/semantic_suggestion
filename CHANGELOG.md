## [4.1.0] - 2026-07-27

Multi-site correctness release. Every fix below was verified on running TYPO3 13.4.22 and
14.3.3 instances, the former configured with two sites.

⚠️ **Upgrading from 4.0.0 requires running the `semanticSuggestionMigrateRootPageId` upgrade
wizard.** See [Upgrading to 4.1.0](README.md#upgrading-to-410) — without it, suggestions
disappear for any analysis whose scheduler task started on a subtree rather than a site root.

### Added
- Bootstrap Package template integration: an opt-in set of page templates that place the
  suggestions after the main content, enabled per site with
  `plugin.tx_semanticsuggestion_suggestions.settings.overrideBootstrapTemplates = 1`
- Upgrade wizard `semanticSuggestionMigrateRootPageId`, which backfills `scope_page_id` and
  rewrites `root_page_id` on existing rows. Rows whose start page no longer belongs to a
  configured site are left untouched and should be regenerated by re-running the task.
- `scope_page_id` column on `tx_semanticsuggestion_similarities`
- French translations for the backend UI strings that were hardcoded (#17)

### Fixed
- **Bootstrap Package template override no longer leaks across sites** (#18): the override is
  now opt-in (`overrideBootstrapTemplates = 0` by default). Because the extension's TypoScript
  is loaded instance-wide, the previous default registered our Bootstrap Package page templates
  for *every* site, blanking the content of any site that used a template named `Default.html`
  without Bootstrap Package. Enable it in the constants of the Bootstrap Package site only.
- **Frontend suggestions are scoped to the current site** (#19): the similarity lookup now
  filters on `root_page_id`, so overlapping scheduler task scopes no longer mix rows from
  different page trees.
- **`maxSuggestions` is honoured again** (#19): the SQL `LIMIT` was applied before the
  `excludePages` and language filters ran in PHP, which could return fewer suggestions than
  configured. Candidates are now over-fetched and the cap enforced after filtering.
- **Per-site cache invalidation actually works** (#20): analysis cache entries are tagged
  `site_<rootPageId>`, the tag `GenerateSimilaritiesTask` has always tried to flush. Until now
  it matched nothing and stale analyses were served for up to 24 hours after a task run.
- **Cache clearing restored on TYPO3 14** (#24): the PSR-14 listener subscribed to
  `AfterDatamapOperationEvent` / `AfterCommandmapOperationEvent`, which exist in no TYPO3
  version, while the working `SC_OPTIONS` hooks were disabled on v14. The hooks are now
  registered unconditionally and the dead listener has been removed.
- **Backend module respects backend user permissions** (#22): non-admin users only see the
  analyses of sites they have a webmount on, and a forged `rootPageId` in the URL no longer
  bypasses that filter.
- The plugin content element renders through `lib.semantic_suggestion` instead of copying the
  plugin configuration object, which is not renderable (#16)
- Suggestion placement corrected in the Bootstrap Package column layouts

### Changed
- **The storage threshold is now exactly `qualityLevel`**, floored at `0.05`, with no offset.
  Four places disagreed on how to derive it: the task constructor applied no offset, the scheduler
  field provider and a dead `SuggestionService::getStorageThreshold()` applied `-0.1`, and the
  `$qualityLevel` docblock documented `-0.1`. The value that actually took effect was the field
  provider's, so a task set to `0.3` stored from `0.2`. All of them now use the single
  `GenerateSimilaritiesTask::getStorageThreshold()`. Tasks store slightly fewer pairs than before;
  those pairs sat below the display threshold and were not shown.
- **The threshold is derived at execution time, not in the constructor.** The scheduler restores
  tasks with `unserialize()`, which never calls `__construct()`, so a stored task ran on whatever
  threshold had been serialized — and the legacy `minimumSimilarity` migration never fired for the
  upgraded tasks it existed for. Both now run at the start of `execute()`.
- **`minimumSimilarity` is a derived, read-only mirror** of the storage threshold. It remains
  declared so existing serialized tasks unserialize cleanly, but setting it has no effect and the
  scheduler no longer accepts it as input.
- **Cache invalidation is scoped per site** (#21): a DataHandler operation now flushes only the
  sites it touched, instead of every analysis of the instance on any record change. Changes to
  tables other than `pages` and `tt_content` no longer trigger a flush at all.
- **`root_page_id` now holds the real site root** (#23), with the scheduler task's `startPageId`
  moved to the new `scope_page_id` column. Analyses of the same site therefore share a
  `root_page_id`, while two tasks covering different subtrees keep separate row sets and no
  longer erase each other.

### Performance
- TF-IDF vectors are computed once per page in `analyzePages()` instead of once per comparison (#15)

### Documentation
- README brought in line with actual behaviour: the `root_page_id` / `scope_page_id` split, the
  upgrade wizard, the instance-wide reach of the extension's TypoScript, backend access control,
  a Multi-Site Setup section, and the `languageId` scheduler parameter. `minimumSimilarity` was
  replaced by `qualityLevel` in the sections describing current behaviour, and left in place where
  the text documents migrating away from it.
- Corrected the install instructions, which told users to run PHPUnit although the extension
  declares no `require-dev` and therefore ships without it.

## changelog [2.0.0-beta] - 2025-03-27

### Added

-   **TYPO3 v13 Support:** Extension fully compatible with TYPO3 v13.x.
-   **Dual Controller Architecture:** Implemented separate backend controllers (`LegacySemanticBackendController` for v12, `SemanticBackendController` for v13+) to handle version differences gracefully.
-   **Conditional Configuration:** Added version checks in configuration files (`Services.php`, `Modules.php`, `Routes.php`) to load appropriate classes and settings for TYPO3 v12 and v13+.

### Changed

-   **Refactored Backend Module:** Adapted backend module logic for compatibility across TYPO3 v12 and v13.
-   **Dependency Injection:** Updated `Configuration/Services.php` to correctly register controllers and their dependencies based on the TYPO3 version.
-   **Module Registration:** Updated `Configuration/Backend/Modules.php` to utilize the appropriate controller class depending on the TYPO3 version.
-   **Code Modernization:** Applied modern PHP features (strict types, return types, Enums) primarily within the v13+ controller (`SemanticBackendController`).

### Fixed

-   **v12 Constructor Error:** Resolved `ArgumentCountError` related to the `SemanticBackendController` constructor on TYPO3 v12 instances.
-   **Backend Statistics:** Corrected `Call to undefined method calculateStatistics` by using correctly prepared statistics data.
-   **Backend Rendering:** Fixed `Call to undefined method setContent` on `ModuleTemplate` by removing manual view rendering and relying on `renderResponse()`.
-   **Backend Template Loading:** Addressed `InvalidTemplateResourceException` (template not found errors like `Default/Index.html`) by explicitly providing the correct template path (`SemanticBackend/Index`) to `renderResponse()`.
-   **v12 Method Signature Compatibility:** Fixed `Fatal error: Declaration of addFlashMessage() must be compatible` by ensuring the DI container registers the `LegacySemanticBackendController` (with the compatible signature) for TYPO3 v12.
